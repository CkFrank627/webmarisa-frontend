# 用户输入审查

服务端启动并接收内容请求后，会在 `RAG_DB_PATH` 指向的 SQLite 数据库中自动创建 `app_input_audit` 表；默认路径为服务端工作目录下的 `data/marisa_rag.db`。不是 MySQL 的问答知识库。

管理员可使用数据库工具执行：

```sql
SELECT id, user_id, username, method, path,
       datetime(created_at / 1000, 'unixepoch') AS received_at_utc,
       content, raw_body
FROM app_input_audit
ORDER BY id DESC
LIMIT 100;
```

`raw_body` 保留服务端收到的完整请求正文；`content` 为便于阅读的 JSON 或解码后的表单内容。查看长字段时打开数据库工具的单元格全文查看器，表格预览可能自行省略文本。用户标识来自有效登录令牌；访客或无效令牌的 `user_id` 为 0，无法据此识别具体个人。

记录覆盖标准/经典/自设聊天、教学、人格创建、留言和会话同步等内容写入请求，在业务处理前落库，业务校验失败的请求也保留。登录和注册接口以及请求头不进入审计记录。客户端本地处理且未提交服务端的命令不在范围内。同步请求包含客户端提交的整个会话快照，可能重复包含历史消息。

审计表独立于聊天记录，清空会话不删除审计记录。写入失败返回 HTTP 503 并停止该次业务处理。记录用于管理员事后审查，不自动判断或拦截敏感内容；不新增公开读取审计记录的接口。

会话存储已取消只保留最后 400 条消息的截断；控制台 `SYNC` 输出仍为摘要，应使用数据库查看全文。此前被截断且客户端也已丢失的内容不能恢复。

部署需重新构建并重启服务端，前端需发布新的构建产物。聊天内容现在按纯文本显示，HTML 标签不会执行，也不会作为富文本渲染。
